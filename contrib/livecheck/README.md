# livecheck — запечатанное сообщение на живом инстансе

Один браузер отправляет текст, другой — **другой контекст, то есть другое
устройство со своим ключом аккаунта** — должен показать его, не перезагружая тред.

Проверка нужна потому, что путей чтения два: перезагрузка идёт через
`GET /api/messages` (там текст оборачивался всегда), а сокет собирался отдельно и
конверта не нёс. 2026-10-25 это выглядело как пустой пузырь у получателя.

Скрипт проверяет и это: **получатель не сделал ни одного `GET /api/messages` после
отправки**. Если текст пришёл бы периодическим опросом, про сокет не было бы
доказано ничего.

## Что нужно

1. Бэкенд с `MEOWCHAT_ATREST_KEY` и своей базой.
2. Фронтенд, собранный с `PINNED_SERVER_KEY_FINGERPRINT`, равным отпечатку этого
   бэкенда (`GET /api/crypto/server-key` → `fingerprint`). Без pin слой выключен по
   замыслу, и проверка покажет старый путь.
   **Отпечаток принадлежит инсталляции, а не репозиторию: после проверки константу
   вернуть в `''`.**
3. Два аккаунта, видимые друг другу в списке.

## Запуск

```sh
npm install                       # playwright-core, драйвит установленный Chrome
APP=http://localhost:4200 \
  SENDER=alice RECIPIENT=bob SENDER_ID=2 RECIPIENT_ID=3 \
  PASSWORD=secret node livecheck.js
```

`SENDER_ID`/`RECIPIENT_ID` — числовые id в базе: по ним открывается `/chat/:id`.

Код возврата 0 — получатель увидел текст вживую и ничего не догружал.

## Чего это не заменяет

Проверки на настоящем телефоне. Здесь Chrome на ноутбуке: он подтверждает, что
цепочка кода цела, но не то, что X25519 доступен в WebCrypto конкретной версии
Safari и что форма пароля после Face ID ведёт себя как надо.
