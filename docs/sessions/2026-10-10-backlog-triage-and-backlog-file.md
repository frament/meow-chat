# Сессия 2026-10-10: разбор Backlog, четыре новые вехи, отдельный BACKLOG.md

## Контекст

Запрос: «проанализировать backlog и распределить его в roadmap». Отдельного `backlog.md`
в репозитории не было — бэклог жил секцией `ROADMAP.md` и копился там с 2026-10-02.

Ничего не исправлялось: работа была только с документацией. Но нашлось три вещи, которые
стоит записать, потому что они меняют, что делать дальше.

---

## 1. Главное: бэклог наполовину устарел

Восемь его пунктов к моменту разбора были **уже исправлены кодом** — они висели открытыми
с 2026-10-03 и вводили в заблуждение при планировании. Ниже — что подтвердилось чтением
кода, а не из истории коммитов:

| Пункт бэклога | Факт |
|---|---|
| Не открывается через LTE | Закрыт: потолок 2 соединения, холодная загрузка 5 запросов вместо 7, плюс два дня правок не действовали из-за старого бандла в кэше SW |
| Сообщения приходят трижды | Закрыт: дедупликация через `Set` рядом с добавлением, а не сканирование массива |
| Нет «нового абзаца» на iPhone | Закрыт: `<textarea>` с авторастом в обеих копиях чата |
| Не прокручивает вниз | Закрыт: обработчик ошибки у `getMessages` + безусловная прокрутка после догрузки |
| WS не восстанавливается | Закрыт: watchdog рукопожатия, `onerror` больше не пустой |
| Плашка «врёт про причину» | Закрыт: `noteLoadFailure(status)` различает 401/403 |
| Ошибки в группах и 15 местах | Почти закрыт: в `chat.ts` остался 1 `subscribe` без error из 41 |
| Догрузка по восстановлению WS | Закрыт: эффект на `wsConnected` в `chat.ts:1419` |

**Цифры тоже разъехались**, причём все три — в сторону «дела больше, чем записано»:

| Записано | Факт |
|---|---|
| 126 маршрутов, harness покрывает 47 (37%) | 133 прикладных маршрута, harness — 83 (**62%**) |
| 16 `subscribe` без `error` | 1 в чате, **13 по всему фронтенду** |
| `chat.ts` 2387 строк, фронтенд 13066 | **2648** и **11719** (без спецификаций) |

Пересчитано скриптом по исходникам с учётом префиксов групп (`api`, `admin`, `fed`, `dev`),
а не на глаз и не по регулярке без префиксов.

> **Урок, который стоит держать.** Файл с бэклогом — не источник истины о состоянии кода.
> Это видно и по трём случаям фиктивных тестов из раунда аудита: там тоже «зелёное» не
> означало «работает». Правило записано в шапку `BACKLOG.md`.

## 2. Открытие: «WebP нельзя миниатюрить» было записано неверно

В бэклоге и в `AGENTS.md` стояло: WebP не пережимается и не получает миниатюры, закрытие
требует CGO, а v2.0.0 CGO убирает.

Проверка по факту: **`golang.org/x/image v0.46.0` уже в `go.mod`**, и в нём есть пакет
`golang.org/x/image/webp` с `Decode`/`DecodeConfig`. WebP декодируется на чистом Go.

Причина отказа лежит в другом месте — `imageproc.Thumbnail` (`imageproc.go:102`) первым
делом проверяет `isJPEG` и для всего остального возвращает `ErrNoThumbnail`:

```go
func Thumbnail(data []byte, maxEdge int) ([]byte, error) {
	if !isJPEG(data) {
		return nil, ErrNoThumbnail
	}
```

То есть сформулировать «нужен CGO» было про блокер в коде, а не про возможности зависимостей.

**Что из этого следует и что нет:**

- **Миниатюры для WebP и PNG делаемы** — результат всё равно JPEG, анимированный WebP отдаст
  первый кадр, что для миниатюры и нужно. Уехало в **v1.5.2**.
- **Оригинал WebP пережать нельзя** — энкодера WebP на чистом Go действительно нет. Это
  правда, и на масштабе инстанса (1 файл из 22 на проде) оно не стоит ничего.

Общее правило: **«сделать нельзя» надо проверять по зависимостям, а не по текущей функции**,
иначе ограничение записывается как свойство языка, хотя это свойство одного `if`.

## 3. Две очереди, обе доведены до таблицы и ни одна до работы

Проверка заодно с бэклогом:

- `INSERT INTO push_copies` — **не встречается в коде ни разу**. Таблица создаётся миграцией
  (`database.go:306`), содержит всё нужное, и строки из неё удаляются в трёх местах:
  `e2ee.go:82`, `handlers.go:434` при успешной WS-доставке, `handlers.go:2431` при удалении
  пользователя.
- `Queue.Enqueue` — вызывается только из `federation/queue_test.go`.

То есть подход «очередь в SQLite с попытками и сроком годности» выбран в проекте **дважды**
и дважды не доведён до работающего состояния. Уборка есть, отправки нет — заведённый контракт
без писателя, что хуже отсутствия таблицы: следующий разработчик примет её за работающую.

Решение: **обе чинятся в одной вехе v1.6.1**. К каждой нужен дренаж, повторы и уборка по TTL;
писать это дважды — значит завести третью половину.

## 4. Решение по вехам

Разбор показал, что пункты бэклога смешаны по размеру: от одной строки (`e2eeReady`) до
рефакторинга, который дешевле делать отдельным заходом. Смешанные они и ехали одним куском.

| Веха | Что переехало | Почему именно сюда |
|---|---|---|
| **v1.5.2** | 13 оставшихся `subscribe` без `error`, миниатюры WebP/PNG, удаление `e2eeReady`, документирование ограничений сжатия | Патч на выпущенную ветку 1.5.x, всё аддитивно, архитектуру не трогает |
| **v1.6.1** | Очередь офлайн-доставки федерации + закрытие `push_copies` | Не фича, а **потеря данных между двумя домами**: сообщение недоступному пиру не доставляется и не сохраняется, а отправитель уверен, что написал. Дальше v2.0.0 это только дорожает |
| **v1.8.0** | Ленивые маршруты, диагностическая панель PWA | Обе части — прямо из жалоб с телефона; продолжают линию `439751a` (1 212 989 → 288 710 Б) |
| **v1.9.0** | Три раунда качества | **До** v2.0.0: он переписывает `main.go` и тестовую обвязку, раунд 2 устарел бы в день написания |

Попутно дописано в существующие вехи: гонки `runHub` + `-race` в CI + SBOM → **v2.1.0**;
версия бандла во фронтенде → **v2.3.0**; плейлист ([#10](https://github.com/frament/meow-chat/issues/10),
открыт с 2026-10-07 и в roadmap отсутствовал) и S3 для `uploads/` → **v2.8.0**; вкладки
настроек → **v2.9.0**.

## 5. TLS оказался недосказанностью, а не разрывом

«Отложенные решения» содержали пункт «TLS после отказа от nginx», а v2.0.0 убирает nginx —
выглядело как разрыв.

Проверка: `contrib/nginx/meow-chat.conf` содержит только `listen 80`. **TLS сейчас
терминируется снаружи** (Cloudflare, роутер, reverse-proxy), значит отказ от nginx HTTPS
не ломает.

Разрыв был в другом: после удаления nginx инструкция по установке обязана сказать это
прямо («TLS — до вас»), иначе человек не поймёт, что делать с HTTPS после обновления.
Записано в веху 0.3 и в «Отложенные решения».

## 6. `BACKLOG.md` вынесен отдельным файлом

Запрос владельца на второй шаг сессии. Файл заведен с шапкой-правилами, которых раньше
нигде не было: только разобранное, уход в веху с пометкой, закрытое не удаляется, **числа
протухают**.

Обоснование выноса: за первые дни жизни бэклога (с 2026-10-02) в нём накопились пункты
**четырёх разных сортов** — ограничения, рефакторинг без вехи, идеи без разбора и история
уже сделанного. Рядом с вехами они читались как единая очередь, хотя половина в очередь
никогда не попадёт.

`ROADMAP.md` похудел с 702 до 534 строк, все девять перекрёстных ссылок переведены на
новый файл. Заодно исправлены ссылки, которые вылезли при разборе: в `AGENTS.md` WebP
миниатюры были названы невозможными (это опровергнуто выше), а очередь федерации была
помечена как «v1.6.0 open» вместо вехи v1.6.1.

## Что не делалось

Кода не тронуто. Тесты не гонялись — правился только текст, а прогон зелёной сборки на
правке документации ничего бы не проверил. Версия не поднималась: изменения не меняют
поведение продукта.
